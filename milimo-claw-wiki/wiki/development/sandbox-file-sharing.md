# Sandbox File Sharing

This guide documents how to access and synchronize files generated by claws inside the isolated sandboxed environment to your host machine.

---

## Accessing Sandboxed Files

Because claws execute within a highly secure, isolated container governed by Linux Landlock LSM policies, their generated files reside on a volume inside the sandbox. Developers can interact with and synchronize these files utilizing three standard methods:
1. **[[#Live Host Synchronization Script]]** (recommended)
2. **[[#Visual Studio Code Dev Containers Explorer]]**
3. **[[#Direct Command Line Extraction]]**

---

## Live Host Synchronization Script

The most direct way to copy files from the claws is using the host-side synchronization script. The script automatically detects the active sandbox container, resolves paths, and extracts files to the local workspace.

### Running the Sync Script

The synchronization script is executable from the workspace root. You can choose to pull files for a single role or all claws simultaneously.

To pull files for all claws, run the script without parameters:

```console
$ ./scripts/pull_claw_files.sh
```

To pull files for a specific claw role (e.g. the build claw), pass the role name:

```console
$ ./scripts/pull_claw_files.sh build
```

### Destination Directory

The script extracts files to the local folder:
`./claws_data/`

This destination directory is pre-registered in the workspace `.gitignore` file to ensure that generated client invoices, content drafts, and local developer assets are kept secure and are never committed to your git history.

## Visual Studio Code Dev Containers Explorer

If you prefer an interactive GUI, you can attach Visual Studio Code directly to the running sandbox container namespace.

### Attaching to the Container

Follow these steps to attach your editor:
1. Install the **Dev Containers** extension in Visual Studio Code.
2. Open the Command Palette using `Cmd+Shift+P` on macOS.
3. Select **Dev Containers: Attach to Running Container**.
4. Choose the active sandbox container from the list. The container name is prefixed with `openshell-my-assistant`.
5. Once attached, select **File > Open Folder** and enter the target path: `/sandbox/`

You can now browse, edit, and copy files directly within the container file hierarchy.

---

## Direct Command Line Extraction

If you need a quick, one-off command without running scripts, you can execute standard Docker commands on your host terminal.

### Extracting a Specific File

To copy a single asset (like `tetris.py` from the build claw repo) directly to your desktop, execute the following command sequence:
1. Find the name of the running container:
   ```console
   $ docker ps --filter "name=openshell-my-assistant" --format "{{.Names}}"
   ```
2. Copy the file from the container to your host:
   ```console
   $ docker cp <container_name>:/sandbox/.openclaw/milimo/claws/build/repo/tetris.py ~/Desktop/
   ```
